# 0065. MCP provider revisions bind the approved tool contract

Date: 2026-10-28

Status: accepted design; implementation pending in plan 12

## Context

Capability overlays already pin a capability id, revision and logical tool names.
MCP adds a remote catalog that can change independently. Pinning names alone cannot
detect a changed schema, and parsing a prefixed display name cannot reliably recover
the remote method. The current execution driver already has canonical schema
digests and protected accepted results; a separate MCP loop or digest system would
weaken those boundaries.

## Decision

Use a versioned operator-owned MCP binding with an explicit approved tool list.
Each tool binds its native remote name, logical name, operator description, input
schema, optional output schema and observation operation class. The binding also
identifies its non-secret server/transport/endpoint binding and protocol limits.
Live endpoint configuration, credentials and connection handles remain outside
agent declarations and journals. Changing endpoint identity changes its binding;
rotating credentials does not redefine the public tool contract. The endpoint
binding id itself commits to the canonical non-secret endpoint/transport; factory
construction verifies that commitment and rejects credential-bearing URLs or a
changed endpoint behind the same id.

Compute the capability revision from the existing canonical `versionedDigest`
with domain `shikigami.mcp-binding/1` over that complete binding, prefixed `mcp-v1-`.
Sort tools by logical name, preserve schema-array order, and retain the existing
canonical object encoding. No generic descriptor field or historical codec change
is required. An operator cannot edit the meaning behind an existing revision:
startup recomputes the digest and pending execution requires the exact binding.

Use explicit remote-to-logical mapping. Final names continue to be generated by
the common `overlay__*` naming owner; native remote calls use the recorded native
name. Do not reverse-engineer names by splitting `mcp__*`. Only approved tools are
exposed. Missing approved tools, duplicate native names or schema differences
refuse acquisition. Extra unapproved remote tools remain unavailable. Remote
descriptions cannot overwrite the approved descriptions. Discovery occurs once
per acquisition; refreshing a live catalog never mutates a pinned registry.

Connect, each discovery request/page and invocation require their respective
fresh C13 action checks for the same principal/capability/revision. Invocation
uses the logical tool target already owned by the common provider wrapper.
Transport authentication is independent. No authorization proof is stored in the
binding or reused as indefinite permission.

The provider obeys the finite count/byte/time ceilings specified in plan 12.
Acquisition owns every opened resource until a successful lease is returned;
thereafter the common bracket owns release. Timeout must have a transport abort
path. The adapter does not retry invocation on its own: execution policy owns
attempt accounting and observation recovery.

Support one-off Skill and durable Skill execution with an accepted exact binding.
Old branches without overlay resolution, legacy conversation branches lacking a
binding, Flow and ShikumiProgram refuse MCP requests explicitly. A retained old
behavior-attempt branch with a pinned overlay is qualified separately for
at-least-once observations. Completed execution-child results replay without the
provider; pending results reacquire the exact binding. Durable mutations remain
excluded under ADR 0025.

## Alternatives rejected

Adding agent-authored endpoints would reintroduce the request/authority confusion.
Accepting discovery as the catalog would let remote changes silently alter an
admitted run. Editing a human-selected revision in place defeats exact lookup.
Adding another generic descriptor schema solely for MCP is unnecessary when its
existing opaque revision can commit to the approved public binding.

Closing a socket is not mutation rollback. A separate MCP retry/tool loop would
hide attempts from existing budgets and replay evidence. Cached discovery
permission would miss revocation between pages or between discovery and invocation.

## Consequences

Operators must retain historical public bindings and exact provider factories for
pending work, and publish a new revision for tool/schema/endpoint-identity changes.
Credential rotation stays independent. A provider may offer many tools while an
agent receives only its approved subset. Unsupported modes fail visibly instead
of running with fewer tools than declared.

Baikai transport and Shikumi adapter releases are still required. Their acceptance
must expose native metadata and bounded cancellation/resource handling. This
decision defines the consumer contract, not a fictional released API.
