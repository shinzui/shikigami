# Current public service contract adoption

ExecPlan 107, 2026-10-30. This records the implemented public API, CLI and
configuration clauses. The full domain/scalar review remains open; this document
is not final release, Linux or external-provider qualification.

The frozen source inventory retains all 124 original source hashes. Each assigned
public API/CLI/config source now has explicit clause dispositions and evidence in
[the machine inventory](../../architecture/keiro-0.22-coverage.json). Optional UI
surfaces are deliberate interface decisions in [ADR-72](../../adr/0072-public-cli-input-is-explicit-and-diagnostics-are-offline.md),
not exclusions based on refactoring cost.

The API package owns one NamedRoutes umbrella shared by server, generated client
and OpenAPI. Application results use typed MultiVerb response lists and handwritten
AsUnion conversions. Native health and Relay pagination retain their public
protocols; the pure `/openapi` route is an explicit single-status document surface.
The obsolete Relay response-body rewrite and its private WAI constructor dependency
are gone. Request-body 400 now declares its real problem schema. Malformed retained
run history is a non-retryable typed 500, distinct from 503 store unavailability and
recorded business failure; the native journal fixture proves payload redaction.

The checked-in document is generated by `shikigami-openapi`. OpenApiSpec checks the
exact methods/statuses/media, wire schemas, operation IDs and security exceptions.
The live `/openapi` fixture checks the served document. Hurl assets are owned by the
API package and included in its source distribution and installed artifact. Their
README separates the explicit safe read suite from authentication, writes and
outage profiles, names fixture cardinality and idempotency assumptions, and uses
private Hurl secrets. The repository orchestrator provisions and removes only its
own PostgreSQL/server/worker fixture. Native fixtures own corruption, cancellation,
listener/feed and collector behavior.

The client now resolves its own leaf Settei schema with built-ins → ordered YAML
files → explicitly bound environment → named flags → ordered overrides. It rejects
bad winners, unknown keys and credential-bearing base URLs. Credential candidates
are redacted, including shadowed candidates. Static discovery now precedes source
IO in the shared and interactive loaders. FIFO process fixtures prove that order;
parser/source/resolution exits are 2/3/4. Existing central Configuration/Diagnostics
option groups derive from the actual parser.

JSON input is explicit (`--stdin` or `--payload -`), bounded and never echoed by
invalid-input diagnostics. Literal arguments do not read stdin. A live accepted-run
roundtrip qualifies stdin and literal idempotent replay, plus actual worker success,
permanent failure, timeout and dependency-outage behavior. The offline process
fixture checks all eleven public binaries' help, versions and three native shell
completion protocols (70 checks total). Nix installs parser-generated completion
assets; their packaged execution remains part of plan95.

The seven-package graph remains intentional. API has no configuration/runtime
edge; the client has no core edge. Client and migration build-identity adapters stay
local rather than introducing a cycle or eighth package. Runtime logging, W3C
propagation, probes and SDK resource release retain their existing focused tests.
The native observed-store/administrative collector evidence is in
[native-inspection-runtime.md](native-inspection-runtime.md).

Current executed counts and profiles are retained in
[haskell-service-results.txt](haskell-service-results.txt). Later language/scalar
changes must rerun affected evidence before final acceptance.

The record pass converts mutable application and supported upstream Generic
records to explicit local `#label` lenses, including fixtures. Callback records
that support Generic now derive it without adding wire instances. The remaining
explicit updates are owning public records without Generic, or higher-rank
capability records such as ExecutionRuntime/SelectionRuntime. GHC 9.12.4 rejects a
minimal Generic derivation containing the same rank-n field with GHC-30367
("must not have exotic unlifted or polymorphic arguments"); ordinary record
updates preserve those capabilities. This is a representability exception, not
permission to duplicate a capability or alter its dispatch/cancellation behavior.
The lexical checker also rejects a missing local Data.Generics.Labels import;
the orphan remains absent from the custom Prelude.

Objective criterion/evidence locators now use distinct abstract CriterionKey and
EvidenceKey types with checked nonempty/bounded admission. Their JSON remains the
same strings. Allocation of ObjectiveId and receipt deduplication are separately
qualified by [ADR-73](../../adr/0073-objective-identity-is-allocated-and-creation-receipts-own-deduplication.md).
The broader domain-scalar inventory remains open.

Objective and assignment revisions now use abstract `StateRevision` values with
nominal scopes for objective state, assignment state, their instruction revisions,
criteria and worker ownership. The name distinguishes these counters from the
existing repository Git `Revision`. Domain command arguments use the same scoped
types; generated/SQL adapters render numbers explicitly. The subsequent worker
extension also carries nominal scopes through objective-version, checkpoint and
ownership provider contracts, rather than flattening those domain interfaces.
Construction/JSON decoding rejects negative counters, and the type exposes no Num,
IsString or Generic instance. Valid JSON remains numeric, including its byte encoding.
The source-owned compile fixture first proves a valid client, then rejects scope
coercion, raw representation coercion and unchecked arithmetic. Transaction guards,
receipt recovery and checkpoint authority remain the existing production paths.

Objective assignment locators and artifact references now join criterion/evidence
keys behind checked private constructors. All four omit Generic, Num and IsString.
The assignment locator retains its established `{"value":"a"}` object codec;
artifact, criterion and evidence references retain JSON strings. Database/provider
adapters refine inputs and unwrap explicitly. Existing concurrent creation,
checkpoint, verifier-backed completion and lost-receipt cases pass unchanged.

Objective prose now has nine private checked types: Title, Goal, Instructions,
CriterionDescription, AttestationStatement, DecisionNote, AssumptionNote,
NextAction and CompletionLimitation. Each retains the existing individual length
policy and JSON string bytes. Show renders a fixed protected marker. Joint list,
graph, encoded-size, revision and authority checks remain at their owning command
boundaries. The pure suite covers empty/oversized admission, exact string encoding
and protected Show; all 545 pure and 375 PostgreSQL tests pass after conversion.

Worker-session state now has its own revision scope; instructions retain distinct
objective/assignment/criteria revisions. Worker ownership uses one worker-owner
scope through messages, checkpoint intents, transfer fences, workspace requests,
admissions, controls and private RPC. SQL parameter codecs unwrap explicitly.
Operator revision/epoch readers refine inputs before runtime acquisition. A
predecessor lookup returns Nothing at zero. The generic scoped codec retains
numeric JSON, while existing concurrency, lost-acknowledgement, stale-owner and
workspace settlement cases exercise the same production transaction paths.
Mailbox sequences/event cursors and the broader resource/identity census remain
under review; these changes do not certify those remaining fields.

Seven additional frozen core/navigation/governance sources now have explicit
clause dispositions. Core compiler/extensions, record/deriving/import conventions,
Prelude isolation and multiline literal use are implemented or verified in source.
Producer-only corpus maintenance is not applicable because no producer pattern
document was changed. Existing timestamp-bound reviews remain historical; no
independent review approval was invented.

The core domain driver now covers all four aggregate witness collections through
concept-owned public facades over the private generated contracts, and invokes the
compiled generated service facade. All 143 assertions pass, including fifteen
focused guard checks with accepted controls and successful replay seeds. Native
unverified guard classifications remain visible. The 545 pure tests pass after
the test-layout extension; see [domain-driver-results.txt](domain-driver-results.txt).
